What you can post.

  • A separate public board from the shop catalog. Off until Enable Classifieds under Settings. A new wallet leaves them off.
  • Goods, services, rentals, jobs, giveaways, and personals.
  • Same key as the shop. No store required.
  • A giveaway, a personal, or a job hire needs no coin node.
  • Goods, a service, a rental, or a job offer stays closed in the app until that wallet's own XBT node or Bitcoin node is connected.
  • The wallet makes the silent-payment code. This page cannot make one. A priced ad with no code still appears.
  • The buyer chooses Pick up or Ship. There is no default.
  • Pick up pays on-chain or with Lightning, in XBT or in BTC.
  • Ship pays with Lightning only. No on-chain.

Post an ad.

A signed note from any Nostr key shows on the wallet board when the note is one this board carries. The poster does not need an Autarki wallet. The rules are on the board rules page.

  • A Nostr extension in this browser signs the note. This page does not ask for a secret key.
  • The note is published to the relay the notice board reads. A note sent only to some other relay never arrives.
  • Classifieds has to be turned on, and the wallet has to be unlocked, or that board stays hidden.
  • Choose one category first. Offer and Hire are shown only for a job. A hire carries no payment code.
  • The title is one line of at most 80 characters. A missing title is dropped.
  • A listing id is 1 to 256 characters with no spaces. Leave it blank and this page chooses one. The same key and the same id replace the note.
  • The description is at most 4000 characters.
  • Country, province, city, and neighbourhood are each one line, at most 40 characters.
  • Use my location asks this browser. The position is not saved and is not sent to Autarki. A refused prompt stops there.
  • The price is a whole number of sats on XBT or BTC. Empty or zero is not payable. A priced ad with no silent-payment code still appears, and the buyer is told it cannot be paid yet. This page cannot make the code. Beside the sats, this page can show an approximate figure in USD or CAD. A place in Canada shows CAD. Any other place shows USD. That figure does not change the sats.
  • A dollar amount, a fraction, or any other currency is shown as text and cannot be paid.
  • Goods, a service, or a rental with a price above zero names 1 to 4 days, and Domestic or Overseas. A job, a giveaway, a personal, a hire, and a zero price publish no ship tags.
  • An image is an https address. Four is the limit. Images are for goods, a service, a rental, or a giveaway.
  • A map link is the https address from OpenStreetMap, Google Maps, or Apple Maps. A map is for goods, a service, or a rental.
  • Ship appears when the note names a public Lightning node for a chain that has a code.
  • Mark sold or Cancel this ad hides the note. A person a wallet has blocked or ignored is hidden on that wallet only.
  • This page checks the note before it is signed. A note this board does not carry is not sent. A report is sent to the Autarki relay. The ad stays on the board. The relay can still keep the original note.
  • Preview this ad shows the note on this page. It does not publish it.
  • Show this ad on other markets posts a second note. That note has no price. The sale stays on the relay this board reads. Turning it off and posting drops that second note. Mark sold and Cancel this ad leave it alone.
  • Accept the board terms before the first note is saved.

The coins stay held.

Pay with Lightning. The coins sit on the seller's node until Mark received.

  1. Name a referee, or nobody.

    • A referee is optional. Each side can name one public name before payment.
    • Payment waits until both sides name the same person, or both name nobody.
    • That person is told when the names match.
    • The referee does not hold the coins. There is no refund button. A return is this hold sending the coins back.

  2. The buyer pays with Lightning.

    • Ship pays with Lightning only. Pick up can still pay on-chain.
    • The coins sit on the seller's Lightning node. They are not in Autarki's hands. The seller can hand the parcel to the carrier knowing the money is already there.
    • The seller's wallet has to stay on through the window. A phone that only opens the page does not hold the coins.
    • Lightning for this is in the AMD and Intel StartOS package, the Ubuntu image, the Umbrel amd64 image file, and Android. The Umbrel community store, Raspberry Pi, Umbrel arm64, and the iPhone build do not start Lightning, so they do not pay a shipment.

  3. Cancel stays open.

    • The ad names two dates. The seller has one to four days to mark it shipped, with a carrier and a tracking number.
    • Before it is shipped, Cancel is still open. The coins go back to the buyer.
    • If the seller does not mark it shipped by the ship-by day, the coins go back.

  4. Mark shipped closes Cancel.

    • After it is shipped, Cancel is closed.
    • The buyer sees the carrier, the tracking number, and a link to the shipper's page.
    • Check the carrier saves the latest scan as words. Canada Post, UPS, FedEx, and DHL are the names it can look up.
    • The person does not create a carrier account. The scan does not pay anyone, and it does not send the coins back.
    • Check the carrier is not on an order already marked received.

  5. Mark received pays the seller.

    • The usual hold after that is 14 days. An overseas ad can say 28 days. The ad shows which one it is.
    • Nora buys a shipped order from Eli. She pays with Lightning. The coins sit on Eli's node. Eli marks it shipped before the ship-by day and enters the carrier and the tracking number. Nora presses Mark received. Eli is paid.
    • If Eli did ship it and Nora does not press Mark received and does not press Not received, Eli is paid when the hold ends. His wallet has to be on for that.
    • If his wallet stays off through the window, the coins go back to Nora.

Pick up does not wait.

Pick up skips this hold. It can pay on-chain or with Lightning. There is still no default.

On-chain has no hold.

Pick up can still pay on-chain. On-chain has no hold, and a referee cannot move those coins. It is not offered for a shipment.

A float comes first.

  • The seller's own coins, so Lightning can arrive immediately.
  • Provide a float records the choice. It does not send coins.
  • On-chain needs no float. Most sellers skip it. In person, Lightning is then not instant.
  • Customer payments replace it. Unspent comes back when the seller stops.
  • A shipped order is not held until a float is set aside.

When it was not received.

Nora presses Not received. She can leave a short note. Eli can leave one too. Not received stops both automatic moves. The coins stay where they are. They do not pay the seller yet, and they do not go back yet.

The coins stay put.

The referee sees the carrier, the tracking number, the saved scan, and those two notes, then gives one decision. The referee does not hold the coins. There is no refund button.

Each side writes one note.

  • The bell shows the other person's note. Opening it does not move the coins.
  • The referee does not hold the coins. A return is this hold sending the coins back.

One decision.

  • A decision for Eli pays Eli.
  • A decision for Nora sends the coins back. The order stays on the books as returned, not cancelled.
  • If no decision arrives, the window still sends the coins back to Nora.
  • If Eli's wallet stays off until the window ends, a decision to pay him does not finish, and the coins return on their own.
  • Mark received closes once a decision is stored.

Four public signs. No star.

None is required to buy or sell. Nobody types a count. No star.

Received shipments

The seller's own book.

  • Completed shipments, the day of the first, and how many are still not received.
  • An online shop reads Received shipments. An opened classified reads the same numbers.
  • Pickup does not count. A counter shop leaves the card off.

Both keys signed

A note from each side.

  • Counts only when each side published a note naming the order and the other key.
  • The note does not name the goods or the price.
  • Shown when that count differs from the stall. Unfinished and the first day stay the stall's.
  • On an order, Completed shipments counts both directions.

Vouch for this key

You said you know this key.

  • Only after the two keys share a completed shipment.
  • The page says You said you know this key. Others are listed as Known by.
  • Otherwise: A vouch follows a completed shipment. A vouch is not a delivery.

Discord

Separate from the counts.

  • Post "Verifying that I control the following Nostr public key:" and the public name.
  • Settings, then Nostr, then Discord. No Save button.
  • The username is the small name, not the display name, and not a User ID.
  • The link starts with https://discord.com/channels/. Publish Discord link saves it.
  • Publishing again replaces it. Remove clears Discord and keeps another site's tag.
  • Autarki does not join Discord and does not check the message.
  • A member of that server can open it. Anyone else still sees the stall.
  • Add to contacts, Unfollow, and Block pay nobody and change no shipment.
  • Unfollow removes that key from the contact list. Block publishes a mute list. Unblock removes it.
  • Postal code, country, and weight. The buyer chooses a shipping price. The item price stays the item price.
  • Set location searches by a city. Use my location asks the browser. The position is not saved and is not sent to Autarki.
